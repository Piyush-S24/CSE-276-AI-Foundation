1A neuron, and why one layer is not enough

Weighted sum, bias, squash. Everything in deep learning is copies of this — but one copy provably cannot compute XOR.

One neuron
z = w1x1 + w2x2 + b,   a = σ(z) = 11 + e−z
Compute z first, then squash. σ(0) = 0.5 exactly, so the decision boundary is wherever z = 0.
The method — what to actually do
  1. Multiply each input by its weight and add the bias → z.
  2. Apply the sigmoid: 1 / (1 + e−z).
  3. Round at 0.5 if a class label is wanted.
  4. For a multi-layer network, do this for every hidden unit first, then feed those outputs forward as the next layer's inputs.
  5. Keep 4 decimals on the hidden activations — rounding them to 0 or 1 early changes the output.
  6. Useful values: σ(−3) = 0.047, σ(0) = 0.5, σ(3) = 0.953, σ(9) ≈ 1.000.
Worked example — the XOR network, all four inputs
A 2–2–1 network. h1 = σ(6x1 + 6x2 − 3); h2 = σ(6x1 + 6x2 − 9); y = σ(8h1 − 8h2 − 4).
  1. Input (0, 0)z1 = −3 → h1 = 0.0474; z2 = −9 → h2 = 0.0001
  2. Its outputz = 8(0.0474) − 8(0.0001) − 4 = 0.379 − 0.001 − 4 = −3.622 → y = 0.0260 → 0 ✓
  3. Input (0, 1)z1 = +3 → 0.9526; z2 = −3 → 0.0474
  4. Its outputz = 8(0.9526) − 8(0.0474) − 4 = 7.621 − 0.379 − 4 = +3.241 → 0.9624 → 1 ✓
  5. Input (1, 0)identical by symmetry → 0.9624 → 1 ✓
  6. Input (1, 1)z1 = +9 → 0.9999; z2 = +3 → 0.9526 → z = −3.622 → 0.0260 → 0 ✓
  7. What the hidden layer inventedh1 fires when at least one input is 1 (an OR unit); h2 fires only when both are (an AND unit)
All four correct. The output computes h1 AND NOT h2, which is XOR. In terms of the two new features the hidden layer built, the problem became linearly separable — and building such features is the entire point of depth.
Practice
  1. A neuron has w = (2, −3), b = 1. Compute its output for x = (2, 1).
    z = 2(2) + (−3)(1) + 1 = 4 − 3 + 1 = 2. σ(2) = 1/(1 + e−2) = 1/(1 + 0.1353) = 0.8808 → class 1.
  2. Show that a single neuron cannot compute XOR.
    It would need b ≤ 0 (for input 0,0 → 0), w1 + b > 0 and w2 + b > 0 (for 1,0 and 0,1 → 1), and w1 + w2 + b ≤ 0 (for 1,1 → 0). Adding the two middle ones gives w1+w2+2b > 0; with the last this forces b > 0, contradicting the first. The system is inconsistent.
  3. Why keep hidden activations to 4 decimals instead of rounding to 0 or 1?
    Because the output layer multiplies them by large weights. Rounding h2 = 0.0474 down to 0 changes z by 8(0.0474) = 0.379, which shifts the sigmoid noticeably. With several layers these rounding errors compound.

2Gradient descent on one weight

Measure the error, work out which direction reduces it, take a small step that way, repeat.

Loss and its slope
L(w) = (wx − y)2,   ∂L∂w = 2(wx − y)x,   w → w − α∂L∂w
The gradient is the outer derivative times the inner one. Note the step subtracts: you move against the gradient.
The method — what to actually do
  1. Compute the prediction wx with the current weight.
  2. Compute the error (prediction − target).
  3. Loss = error2.
  4. Gradient = 2 × error × x.
  5. New w = old w − α × gradient.
  6. Recompute the loss to confirm it fell. If it rose, α is too large.
  7. Notice the steps shrink automatically as the gradient flattens near the minimum — no extra logic is needed.
Worked example — four steps to the optimum
One training example: x = 3, y = 6, so the optimum is w = 2. Start at w = 1 with α = 0.05.
  1. Step 0 — current stateprediction 1(3) = 3; error 3 − 6 = −3; loss = (−3)2 = 9.000
  2. Gradient2(−3)(3) = −18.0
  3. Updatew = 1 − 0.05(−18.0) = 1 + 0.9 = 1.900
  4. Step 1 — check the loss fellprediction 1.9(3) = 5.7; error −0.3; loss = 0.090, down from 9.000
  5. Gradient now2(−0.3)(3) = −1.8 — ten times smaller
  6. Updatew = 1.9 + 0.09 = 1.990, loss 0.0009
  7. Steps 3 and 4w = 1.999 then 1.9999; loss → 0
  8. What happened to the step sizes0.900, then 0.090, then 0.009 — each ten times smaller than the last
Converges to w = 2.0, loss 0. The steps shrank automatically because the gradient shrinks as the minimum nears. Nothing told the algorithm to slow down — it falls out of the arithmetic.
Practice
  1. With x = 2, y = 10, w = 3 and α = 0.1, compute one step.
    Prediction 3(2) = 6; error 6 − 10 = −4; loss = 16. Gradient = 2(−4)(2) = −16. New w = 3 − 0.1(−16) = 3 + 1.6 = 4.6. New loss: 4.6(2) = 9.2, error −0.8, loss = 0.64.
  2. Using the same setup but α = 1.0, what happens?
    New w = 3 − 1.0(−16) = 19. Prediction 38, error +28, loss = 784 — far worse than the 16 we started with. The step overshot the minimum and landed much further up the other side. This is what a divergent learning rate looks like.
  3. Why does the gradient contain a factor of x?
    Because of the chain rule: the loss depends on w through the prediction wx, and ∂(wx)∂w = x. Practically, it means a weight attached to a large input gets a larger update — which is part of why unscaled features make training unstable.

3Parameter counts, cost and latency

Three calculations that decide real architecture choices, and none of them is about accuracy.

Parameter counts
dense: (nin + 1)nout,   conv: (F·F·Cin + 1)Cout
The conv count has no image-size term — the same filter is reused at every position. That is the entire saving.
The method — what to actually do
  1. Dense: (inputs + 1) × neurons. The +1 is the bias.
  2. Conv: (filter × filter × input channels + 1) × number of filters.
  3. Break-even: set (cost from scratch) × k = pre-train + (adapt × k) and solve for k.
  4. Latency budget: 1 / loop rate, in seconds. Convert to milliseconds.
  5. Compare the model's inference time against that budget.
  6. If it does not fit, no amount of accuracy rescues it — latency is a correctness constraint, accuracy only a quality one.
  7. Blind distance = speed × latency, which is usually the number that persuades people.
Worked example — the three calculations, on one system
A robot vision system. Images are 224×224 RGB. The robot moves at 1.5 m/s and its control loop runs at 50 Hz.
  1. Dense first layer of 64 unitsinputs = 224 × 224 × 3 = 150 528 → (150 528 + 1) × 64 = 9 633 856 parameters
  2. Conv layer, 64 filters of 3×3 over 3 channels(3 × 3 × 3 + 1) × 64 = 28 × 64 = 1 792
  3. Ratio9 633 8561 792 ≈ 5 376× fewer
  4. Now the economics. From scratch ₹40 000 per task; pre-train ₹10 lakh then ₹500 per task40 000k = 10 00 000 + 500k → 39 500k = 10 00 000 → k ≈ 25 tasks
  5. Below 25 taskstraining from scratch is cheaper; above it, pre-training wins and the gap widens fast
  6. Latency budget150 Hz = 0.02 s = 20 ms per cycle
  7. Cloud model at 260 ms260 > 20 → misses 13 cycles; blind distance = 1.5 × 0.260 = 0.39 m
  8. On-device model at 18 ms18 < 20 ✓; blind distance = 1.5 × 0.018 = 0.027 m
5 376× fewer parameters, break-even at 25 tasks, and 39 cm versus 3 cm of blind travel. The last one decides the architecture: the 88%-accurate on-device model is the correct engineering choice over the 98% cloud model, because latency here is a correctness constraint.
Practice
  1. How many parameters in a dense layer with 500 inputs and 200 neurons?
    (500 + 1) × 200 = 501 × 200 = 100 200. The 200 bias terms are the difference between this and the naive 100 000.
  2. A drone flies at 20 m/s and must react within 2 m. What is the maximum acceptable inference latency?
    time = distance / speed = 2 / 20 = 0.1 s = 100 ms. Any model slower than 100 ms cannot keep the drone inside its 2 m reaction envelope, regardless of accuracy.
  3. Pre-training costs ₹50 lakh, adapting costs ₹2 000 per task, and training from scratch costs ₹60 000 per task. Break-even?
    k = 50 00 000 / (60 000 − 2 000) = 50 00 000 / 58 000 ≈ 86 tasks. Below 86 tasks, train from scratch; above it, pre-train. Raising the adaptation cost pushes the break-even point up.
