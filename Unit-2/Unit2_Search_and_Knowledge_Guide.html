Part A — Problem Solving using Search

1 · What "uninformed" actually means

The algorithm knows the rules of the world but has no idea which direction the goal lies in.

The input every search takes

A search algorithm consumes exactly the five-component problem definition from Unit I. That is why formulation came first — the algorithm is written once and works on any problem you can state this way.

initial state S₀
actions A(s)
transition model Result(s, a)
goal test — a predicate, not a state
path cost c(s, a, s′)

A solution is a path from S₀ to a goal state. An optimal solution is the cheapest such path.

The frontier

Search keeps one list: the states it has generated but not yet expanded. This is the frontier (or "open list"). The entire difference between search algorithms is which item you take out of the frontier next.

Queue → take the oldest → Breadth First
Stack → take the newest → Depth First
by g(n) → cheapest so far → Uniform Cost
by h(n) → looks closest → Best First
by g+h → best total guess → A*
Remember thisOne line of code — which end of the list you pop from — changes completeness, optimality and memory.

What it may and may not use

  • May use: the problem definition only — states, legal actions, the transition model, the goal test, step costs.
  • May not use: any estimate of how far the goal still is. That estimate is a heuristic, and using one makes the search informed.

The consequence is that uninformed search must explore systematically, and systematic exploration becomes expensive extremely fast — bd states at depth d.

Also calledBlind search.

Why DFS uses so little memory DFS only ever stores the nodes on the current path plus their unexpanded siblings — that is b nodes per level, m levels deep, so b·m. BFS must hold an entire level at once, and the last level has bd nodes. Space is usually what kills you first, not time.

3 · "BFS is optimal" — the clause students forget

BFS minimises the number of edges, not the cost. On a weighted map those are different things.

Where the claim breaks

BFS has no notion of cost, so it treats every edge as costing 1 and returns the route with the fewest hops. On a road network the route with the fewest junctions is frequently not the shortest in kilometres.

Gate ──300── Library ──200── Canteen 2 edges, 500 m Gate ──450── Block32 ──260── Canteen 2 edges, 710 m Gate ────────── 900 ────────── Canteen 1 edge, 900 m ← BFS picks this
Write it precisely “BFS is optimal when all step costs are equal.” The clause is the answer.

The fix: Uniform Cost Search

Expand the frontier node with the lowest path cost g(n) rather than the shallowest one.

f(n) = g(n)   — cost already paid, nothing else
  • Complete and optimal on any graph with non-negative step costs.
  • It reduces to BFS exactly when every step costs the same.
  • It is also what A* becomes when the heuristic is h(n) = 0.
Exam-safe summary BFS: complete, optimal if step costs equal, O(bd) time and space. DFS: incomplete in infinite spaces, not optimal, O(b·m) space.

4 · The three functions of informed search

Uninformed search uses only g. Best First uses only h. A* uses both. That single sentence organises the whole half-unit.

g(n) — the cost already paid

g(n) = actual path cost from the start to n

Known exactly, because you travelled it. Add up the step costs along the path you took.

h(n) — the heuristic estimate

h(n) = estimated cost from n to the goal

A guess you supply using knowledge of the problem. Straight-line distance for route planning; Manhattan distance for the 8-puzzle. h(goal) = 0.

f(n) — the evaluation function

f(n) = g(n) + h(n)

Estimated total cost of a path that goes through n. A* always expands the frontier node with the smallest f.

Admissibility — the condition for A* to be optimal

h(n)  ≤  true cost from n to the goal,  for every n

The heuristic must never overestimate. An optimistic heuristic keeps A* optimal; an overestimating one can push the genuinely best path down the queue so it is never expanded — A* still returns a solution, just not necessarily the cheapest one.

Dominance If h₂ and h₁ are both admissible and h₂(n) ≥ h₁(n) for every n, then h₂ dominates h₁. A heuristic closer to the truth prunes more, so A* with h₂ never expands more nodes than A* with h₁.
Careful Admissible allows h(n) = true cost. It must simply never go above it. h(n) = 0 is admissible too — and turns A* into Uniform Cost Search.

5 · Three informed strategies

All three use a heuristic. They differ only in what else they take into account.

Strategy 1

Best First Search greedy

f(n) = h(n)
  • Expands whichever node looks closest to the goal.
  • Fast, and often finds a solution quickly.
  • Not optimal — it ignores the cost already paid.
  • Can be led badly astray by a misleading heuristic.
Strategy 2

Hill Climbing local search

move to the neighbour with the best h; keep no frontier
  • Constant memory — it stores only the state it is standing on.
  • Never looks back, never keeps alternatives.
  • Stops at a local optimum, plateau or ridge.
  • Fixes: random restarts, simulated annealing.
Strategy 3

A* Search the one to reach for

f(n) = g(n) + h(n)
  • Complete and optimal when h is admissible.
  • Optimally efficient — no algorithm with the same heuristic expands fewer nodes.
  • Cost: it stores the frontier, so memory is the limit.

The trade-off in one line

A*pays memory for a guarantee. Hill Climbingpays the guarantee for memory. Best Firstsits between the two — cheap and fast, no promises. h(n) = 0collapses A* into Uniform Cost Search.

6 · Why Hill Climbing gets stuck

Local optimum, plateau and ridge — the three shapes that stop it, and the two standard escapes.

climber where it stopped global optimum

Run it yourself

The curve is an objective we want to maximise. The climber only ever looks at its two immediate neighbours and steps to a better one.

Local optimumevery neighbour is worse, but you are nowhere near the goal. It stops anyway. Plateaua flat region — all neighbours are equal, so there is no signal about which way to go. Ridgea narrow rising path where every single-step move goes down, although progress is possible diagonally.
Fix 1 · Random restartsWhen stuck, start again from a new random state and keep the best result. Cheap, and surprisingly effective.
Fix 2 · Simulated annealingSometimes accept a worse move, with a probability that decreases over time, so the search can escape a local optimum early on and settle later.

Part B — Knowledge Representation & Reasoning

9 · Why represent knowledge at all?

Search finds a path, but it must explore. Knowledge lets a machine skip the exploring.

Knowledge replaces search

If you already know that a bishop stays on one colour, you never search the moves that break the rule. Every fact you encode is a branch you never expand.

The historical turnAfter the first AI winter the field's answer was to stop searching harder and start encoding what experts know.

What a representation must do

  • Expressive enough to say what you mean.
  • Structured enough for a machine to reason over.
  • Ideally explainable — you can show why a conclusion follows.

Those three pull against each other, which is why several representations exist rather than one.

The four you must know

Semantic networksconcepts as nodes, relations as labelled edges. Framesone record of slots and values per concept. Production systemsIF–THEN rules plus an engine that fires them. Logicpropositional and first-order predicate logic.
They are not rivals. Real systems combine them, and each makes different things easy.

10 · Semantic networks and frames

Both give you inheritance. One is built from edges, the other from records.

Semantic network click a concept

Nodes are concepts; labelled directed edges are relationships. The two relations you must name are is-a (class membership) and has-a (properties).

Inheritance: a property stated at a general node is inherited by everything below it — state it once, and every descendant gets it.

Good fortaxonomies, class hierarchies, anything where relationships dominate. Weak forprocedures, exceptions, and quantified statements.

Frames

A frame is a record-like structure holding the properties of a single concept in named slots. This is where object-oriented programming came from.

FRAME: Penguin
  is-a     : Bird
  can-fly  : false  ← overrides the default
  habitat  : Antarctica
  colour   : black and white
  covering : feathers  ← inherited from Bird
  • Defaults: a slot can carry a default value that a more specific frame overrides.
  • Inheritance: frames link to parent frames, so unfilled slots fall back.
  • Good for structured objects with typical values.
  • Weak for arbitrary relations between objects, and reasoning that is not slot lookup.

Network or frame? how to decide in an exam

Classic exam line “Which representation lets you state every student has a roll number once rather than repeating it for each student?” — a semantic network with inheritance, or first-order logic with ∀. Propositional logic has no quantifiers, so it needs one statement per student.

11 · Production systems and expert systems

IF–THEN rules plus an engine that fires them — and the two directions that engine can run in.

A production rule

IF <conditions> THEN <action or conclusion>

The conditions are matched against the facts currently known. If they all hold, the rule may fire and its conclusion is added to what is known.

The three components

Knowledge basethe rules — long-term, written by an expert. Working memorythe facts known right now — short-term, changes as the system runs. Inference enginedecides which rule fires next and applies it.
Conflict resolutionWhen several rules match at once, the engine must choose one — by specificity, recency, or an explicit priority.

Expert systems

  • Explanation facility: because reasoning is a chain of named rules, the system can show why it concluded something. This is why expert systems survive in medicine and law.
  • Limit 1 — brittleness: outside the rule set, behaviour is undefined.
  • Limit 2 — the knowledge acquisition bottleneck: every rule must be extracted from a human by hand. Together these two caused the second AI winter.

Forward vs backward chaining

Same rule base, same facts, two directions. Step through both and watch what the engine does.

Working memory

Forwardstart from the facts, fire every rule whose conditions hold, add conclusions, repeat until nothing new appears. Best when you have data and want to know what follows. Backwardstart from a hypothesis and work backwards, asking what would have to be true. The natural choice for diagnosis.

12 · Propositional vs first-order predicate logic

Quantifiers are the whole difference: the ability to say "for all" instead of listing every case.

Side by side

Propositional logicFirst-order predicate logic
Basic unitA whole statement that is true or falseObjects, predicates over them, and relations
ExampleRainingToday = True∀x Human(x) → Mortal(x)
Generalises?No — state every case separatelyYes — one rule covers all objects
QuantifiersNone∀ (for all), ∃ (there exists)
Expressive powerLimited — n objects need n statementsHigh — one statement covers a domain
Decidable?Yes — truth tables always terminateSemi-decidable — proofs may not terminate
Use it forSmall fixed sets of conditions, circuits, simple rulesDomains with many objects and general laws

What the quantifiers actually claim

∀x Student(x) → HasRollNo(x)
“every object that is a student has a roll number”

∃x Student(x) ∧ Topper(x)
“at least one student is a topper” — it says nothing about how many
The pairing rule ∀ almost always pairs with → (implication); ∃ almost always pairs with ∧ (conjunction). Writing ∀x Student(x) ∧ HasRollNo(x) claims everything in the universe is a student — a standard exam trap.
Why FOL costs more Propositional logic is decidable: build the truth table and you always get an answer. FOL is only semi-decidable — if a sentence follows, a proof exists and will eventually be found; if it does not, the search may run forever.

13 · Reasoning under uncertainty — Bayes' theorem

Logic handles what is certainly true. Bayes handles what is probably true.

P(disease | positive test)

—

has the disease & tests positive healthy but tests positive has the disease, test missed it healthy, negative

The theorem

P(H | E)  =  [ P(E | H) · P(H) ]  /  P(E)

posterior  =  ( likelihood × prior ) / evidence
P(H)the prior — how common the hypothesis is before any evidence. P(E|H)the likelihood — how expected the evidence is if H holds. P(H|E)the posterior — the updated belief. P(E)the evidence — total probability of seeing E at all.
P(E) = P(E|H)·P(H) + P(E|¬H)·P(¬H)  ← how you actually compute it

Move the sliders and watch the base rate win.

The worked example you must be able to reproduce

1

Write down what you know. P(D)=0.01, P(¬D)=0.99, P(+|D)=0.90, P(+|¬D)=0.05

2

Numerator. P(+|D)·P(D) = 0.90 × 0.01 = 0.0090

3

The other contribution. P(+|¬D)·P(¬D) = 0.05 × 0.99 = 0.0495

4

Total probability of a positive test. P(+) = 0.0090 + 0.0495 = 0.0585

5

Apply Bayes. P(D|+) = 0.0090 / 0.0585 = 0.1538

The answer About 15% — despite a positive result from a 90%-sensitive test.
Why so low — the base rate fallacy The disease is rare. There are far more healthy people, so 5% of a large healthy group produces more false positives than 90% of a tiny sick group produces true positives. Most people guess around 90%; this is the most common error in probabilistic reasoning, and it is why screening programmes retest before diagnosing.
Where it appears Medical diagnosis, spam filtering, sensor fusion, fault detection — anywhere a system must act on evidence that is suggestive rather than certain.

14 · The eight ideas worth remembering

If you revise nothing else the night before, revise these.

Part A — search

1

Uninformed search knows the rules but not the direction. BFS and DFS use only the problem definition — no estimate of how far the goal is.

2

BFS and DFS differ by one line. A queue gives breadth-first; a stack gives depth-first. That single choice changes completeness, optimality and memory.

3

BFS is optimal only when step costs are equal. It minimises edges, not cost. Weighted graphs need Uniform Cost Search or A*.

4

A heuristic must never overestimate. Admissibility is the condition for A* to be optimal; an overestimate can lose the best path.

5

A* uses f(n) = g(n) + h(n). Cost already paid plus estimated cost remaining. With h = 0 it becomes Uniform Cost Search.

6

Hill Climbing trades the guarantee for memory. Constant memory, but it stops at local optima, plateaus and ridges. Random restarts and annealing are the standard fixes.

Part B — knowledge

7

Knowledge representation was the answer to the first winter. Semantic networks, frames, production systems and logic all encode what an expert knows so the machine need not search for it.

8

Bayes' theorem handles uncertainty. Posterior = likelihood × prior / evidence. A positive test for a rare disease still leaves the disease unlikely.

Four pitfalls that cost marks

1Saying “BFS is optimal” without the equal-cost clause. 2Confusing complete with optimal — they are different properties. 3Saying an admissible heuristic must underestimate. It must never overestimate; equalling the true cost is allowed. 4Answering “90%” to the Bayes medical-test question.
